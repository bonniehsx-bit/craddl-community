# JXMall V2 商户端(MCH)商品集成与渲染架构规范

本文档详述了如何将**任意业务插件**的「商品发布与编辑」统一整合到商户端，并使用全局统一的 `GoodsEditDrawer` 抽屉体系。这消除了旧版不同插件在商户端各自维护冗长表单(goods-edit.vue / GoodsEditForm.php)带来的强耦合与高维护成本。

为了防止类似问题的再次发生，在进行相关商户端组件开发时，请严格遵守以下开发规范！

## 一、 前端组件使用规范

### 1. 禁用旧式级联路由编辑
所有涉及“新建/编辑商品”的操作，不论在哪个插件目录下，**禁止**保留单独的 `goods-edit.vue` 视图级路由页面。
所有的编辑交互**必须在列表页 `index.vue`** ，通过 `el-table` 直接弹出全局注册的 `<goods-edit-drawer>` 来呈现无缝的侧边栏。

### 2. 标准化前端 `index.vue` 范例与重要约束

在构建 `index.vue` 的列表与编辑页面时，一定要参考以下最佳实践范例：

```vue
<template>
  <div class="app-container">
    <el-card shadow="never">
      <!-- 1. 列表头部筛选器（必须补齐审核筛选） -->
      <div class="filter-container">
        <el-form :inline="true" :model="search" size="small">
          <el-form-item label="商品名称">
            <el-input v-model="search.keyword" placeholder="请输入商品名称" clearable @keyup.enter.native="searchList"></el-input>
          </el-form-item>
          <!-- [规范点 1] 必须强制补全 is_check 的商户侧前端筛选项 -->
          <el-form-item label="审核">
            <el-select v-model="search.is_check" placeholder="审核状态" clearable style="width: 150px;" @change="searchList">
              <el-option label="全部状态" value="-1"></el-option>
              <el-option label="待审核" value="0"></el-option>
              <el-option label="已通过" value="1"></el-option>
              <el-option label="未通过" value="2"></el-option>
            </el-select>
          </el-form-item>
          <el-form-item>
            <el-button type="primary" @click="searchList">搜索</el-button>
            <el-button type="success" icon="el-icon-plus" @click="handleAdd">新增商品</el-button>
          </el-form-item>
        </el-form>
      </div>

      <!-- 2. 表格展示部分 (必须渲染是否通过审核) -->
      <el-table :data="list" border size="small">
          <!-- 这里省略商品图文展现部分... -->
          <el-table-column label="审核状态" align="center" width="100">
              <template slot-scope="{row}">
                  <el-tag v-if="row.is_check === 0" type="warning" size="small">待审核</el-tag>
                  <el-tag v-else-if="row.is_check === 1" type="success" size="small">已通过</el-tag>
                  <el-tag v-else-if="row.is_check === 2" type="danger" size="small">未通过</el-tag>
                  <span v-else>--</span>
              </template>
          </el-table-column>
          <el-table-column label="操作" width="150" align="center" fixed="right">
            <template slot-scope="scope">
              <!-- [规范点 2] 所有的编辑动作只需绑定 `currentEditId` 等唤起抽屉即可 -->
              <el-button type="text" size="small" icon="el-icon-edit" @click="handleEdit(scope.row)">编辑</el-button>
            </template>
          </el-table-column>
      </el-table>
    </el-card>

    <!-- 3. [核心！] 全局抽屉编辑器组件挂载 -->
    <!-- [规范点 3] 必须引入 global component 中的 goods-edit-drawer -->
    <goods-edit-drawer 
        :visible.sync="editVisible" 
        :goods-id="currentEditId" 
        goods-type="YOUR_PLUGIN_NAME"
        api-url="/plugin/YOUR_PLUGIN_NAME/admin/goods/edit" 
        :disable-multi-spec="true" 
        :require-mch="false"
        :hidden-tabs="['express', 'property', 'integral', 'member_price', 'permission', 'status']" 
        @success="searchList">
        
        <!-- [规范点 4] 使用 extra-tabs 构建特有插件业务面 -->
        <template #extra-tabs="{ form }">
            <el-tab-pane label="你的插件配置规则" name="my_plugin" v-if="form.plugins_data && form.plugins_data.YOUR_PLUGIN_NAME">
               <el-card shadow="never">
                 <el-form-item label="自定义表单项">
                   <el-input v-model="form.plugins_data.YOUR_PLUGIN_NAME.custom_field"></el-input>
                 </el-form-item>
               </el-card>
            </el-tab-pane>
        </template>
    </goods-edit-drawer>
  </div>
</template>

<script>
import GoodsEditDrawer from '@/components/goods/GoodsEditDrawer.vue'

export default {
  components: { GoodsEditDrawer },
  data() {
    return {
      list: [],
      search: { keyword: '', is_check: '-1', page: 1 },
      // 抽屉联动开关与编辑ID
      editVisible: false,
      currentEditId: 0
    }
  },
  methods: {
    searchList() {
        // 请求后台 Controller 获取列表
    },
    handleAdd() {
      this.currentEditId = 0; // 为 0 意为新增
      this.editVisible = true; // 唤出抽屉
    },
    handleEdit(row) {
      this.currentEditId = row.id; // 传递实体 ID
      this.editVisible = true; // 唤出抽屉并自动发送包含此 ID 的 api-url 请求内容
    }
  }
}
</script>
```

### 3. 组件 Props 设置指南 (致命警告区)

*   **[`api-url`]** *(绝对核心)*：商家侧的抽屉 `api-url` **必须**指向当前插件下的 `admin` 命名空间接口（如上方例子代码 `/plugin/YOUR_PLUGIN_NAME/admin/goods/edit`）。
    *   **排误警告**：**绝对不能错误联接到 `/plugin/mch/mall/goods/edit`**！因为该路由是供商户控制台的顶级总管理员(`mall`域)用的，会触发对商户未登录(超级管理员)的越权错误 (`code: -1`)。
*   **[`goods-type`]**：填写你的插件名称，由于原生的验证类会对这个值做严格约束，请和它在 DB（`jxmall_goods.type`）里的名字严格保持一致。
*   **[`disable-multi-spec`]**：如果你这个插件业务像“酒店”、“团购”一样没有复杂的尺码大小规格，请强制传递为 `true`。
*   **[`hidden-tabs`]**：使用该数组参数以砍去该商品无需具备的面板组合。如：你本身不发实物，那就要排除 `['express']` 面板；如果不做会员打折，那么排除 `['member_price']`。
*   **[`#extra-tabs`] (插槽开发)**：通过在内部直接写 `v-if="form.plugins_data && form.plugins_data.YOUR_PLUGIN_NAME"` 就能立刻取得后端给你抛出来的安全响应上下文对象。所有的内部嵌套直接使用 Element 官方标准 `v-model` 去映射底层该树的数据即可。

## 二、 后端读取与存储规范

鉴于原生的 MCH 基础表单（`\app\plugins\mch\forms\admin\goods\GoodsEditForm`）属于**商家域底层**，很多在“商城总后台 `mall`域”才会原生支持的事件发射它并没有做预写，开发商户商品的插件表单时需手动兼容：

### 1. 后台 `GoodsEditForm.php` 的完美继承形态

一个合法且健全的商户插件商品编辑表单（例如 `group\GoodsEditForm`），必须长这个样子：

```php
<?php
namespace app\plugins\your_plugin\forms\admin;

use app\core\ApiCode;
use app\plugins\your_plugin\models\YourPluginGoods;

class GoodsEditForm extends \app\plugins\mch\forms\admin\goods\GoodsEditForm
{
    // [致命坑点 1] 必须补充声明此公共变量！
    // 否则 POST 提交的 plugins_data 会被默认表单由于无安全规则而在 $form->attributes 时静默丢弃！
    public $plugins_data;

    // [致命坑点 2] 必须声明校验 safe，从而被 Yii 的 params 拦截器放行注入
    public function rules()
    {
        return array_merge(parent::rules(), [
            [['plugins_data'], 'safe'],
        ]);
    }

    // 强行改变存表时的 Goods::type
    protected function getFormGoodsType()
    {
        return 'your_plugin_name';
    }

    // [致命坑点 3] 手动构建响应的 plugins_data (因为原生 MCH 读取商品并不包含插件解析)
    public function getDetail()
    {
        $res = parent::getDetail();
        if ($res['code'] !== ApiCode::CODE_SUCCESS) return $res;

        // 注意：MCH底层查回来的主数据存在 info 节点，而 NOT detail，千万别读错覆盖了！
        $detail = $res['data']['info'];
        
        $pluginGoodsConfig = null;
        if ($this->id) {
            $pluginGoodsConfig = YourPluginGoods::findOne(['goods_id' => $this->id, 'is_delete' => 0]);
        }
        
        // 覆盖写入由 Listener 可能触发或未能触发的插件字段结构
        // 此结构会被前端 <goods-edit-drawer> 的 vue $set 进行动态解析转换成 Object
        $detail['plugins_data'] = [
            [
                'key' => 'your_plugin_name',
                'data' => [
                    'custom_field' => $pluginGoodsConfig ? $pluginGoodsConfig->custom_field : 'default_val',
                ]
            ]
        ];
        
        // 装填回去
        $res['data']['info'] = $detail;
        return $res;
    }
}
```

### 2. 利用流水线 Event 抛出数据入库方案 (`GoodsListener`)

由前面步骤保障了 `$this->plugins_data` 的完整接入并流转进后端的核心 `GoodsEventDispatcherPipe`。此时所有处理流交棒到了 `yuda` 或者 `group` 的 `GoodsListener.php`！

你只需要监听 `GoodsEvent::GOODS_AFTER_SAVE` 进行持久化即可：

```php
    public function save(GoodsEvent $event)
    {
        // 1. 判断货物归属插件类型
        if ($event->goods->type !== 'your_plugin_name') {
            return;
        }

        // 2. 取出经过 GoodsEditForm.php 放行的前端提交的数据结构
        $data = $event->pluginData['your_plugin_name'] ?? null;
        if (!$data) {
            // 如果前端或 rules 未传送就会产生静默拦截
            return;
        }

        // 3. 执行你的附加表操作，这部分和 mall 的 goods-edit 环境逻辑同构
        $pluginModel = YourPluginGoods::findOne(['goods_id' => $event->goods->id]);
        if (!$pluginModel) {
            $pluginModel = new YourPluginGoods();
            $pluginModel->goods_id = $event->goods->id;
            ...
        }
        
        // ...执行赋值与 $pluginModel->save() 等
    }
```
结合这篇核心说明指南，未来新增或改造第三方插件支持商家独立编辑发布商品时，将不再畏惧前端的参数消失和样式缺失等疑难杂症。
